## Overview

Use [`embed()`](/sdk/reference/api#embed) from the SDK to generate vectors and store them in the database of your choice. This path gives you full control over persistence, filtering, and integration with existing infrastructure.

<Callout type="info">
  When using an external vector DB, make sure its schema matches the embedding
  dimensionality produced by your model (e.g., GTE Large embeddings are
  1024-dimensional).
</Callout>

## MongoDB

This example needs a MongoDB driver and a deployment with Atlas Vector Search. Install the driver for the language you are using — `npm i "mongodb@^7.5.0"` for JavaScript and TypeScript, or `pip install "pymongo>=4.13"` for Python. Those are the versions these docs are tested against.

One way to get a deployment is the Atlas local container:

```bash
docker run -p 27017:27017 --name atlas-local mongodb/mongodb-atlas-local
```

The script connects to `mongodb://localhost:27017/?directConnection=true`; edit that connection string if your deployment lives elsewhere.

The following script stores each document in MongoDB alongside its vector, builds a vector search index over it, and retrieves matches with a `$vectorSearch` aggregation that [pre-filters](https://www.mongodb.com/docs/vector-search/query/aggregation-stages/vector-search-stage/#pre-filter-search-data) by category:

## SQLite

This example needs the vector extension for SQLite, which arrives differently per language. JavaScript and TypeScript use a SQLite WASM build that has the extension compiled in; Python uses the standard library's `sqlite3` module and loads the extension from a prebuilt binary. Install the one for the language you are using:

```bash
# JavaScript and TypeScript
npm i "@sqliteai/sqlite-wasm@3.50.4-sync.0.8.30-vector.0.9.23"

# Python
pip install "sqliteai-vector>=1.1"
```

Those are the versions these docs are tested against. Loading an extension also needs a Python configured with `--enable-loadable-sqlite-extensions`. Most distribution and python.org builds are; `pyenv`'s default build is not, and no package you install changes that — pass `-p` to `virtualenv` (or `--python` to `uv venv`) to base the environment on an interpreter that qualifies. The example checks before it starts and tells you if yours does not. The database is in-memory, so there is nothing else to set up.

The driver always supports loadable extensions, but the vector extension itself is a prebuilt binary: download the one for your platform from the [sqlite-vector releases](https://github.com/sqliteai/sqlite-vector/releases) and point `SQLITE_VECTOR_EXTENSION` at it:

```bash
SQLITE_VECTOR_EXTENSION=/path/to/vector ./gradlew -p examples run -Pexample=RagSqlite
```
