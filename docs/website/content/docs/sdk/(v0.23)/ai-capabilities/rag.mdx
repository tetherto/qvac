## Overview

RAG (retrieval-augmented generation) uses [text embeddings](/sdk/ai-capabilities/text-embeddings): you embed (vectorize) documents, persist them in a vector store, and later retrieve the most relevant chunks for a query using similarity search.

Compared to generating text embeddings only, the key differences are:
- You must **persist embeddings** (vectors) alongside the original text (and optional metadata) in a vector store.
- At query time, you **embed the query** and run **top‑K** vector search to fetch the most relevant documents/chunks.
- You _typically_ pass the retrieved text to [`completion()`](/sdk/reference/api#completion) as context to ground the model's answer (this retrieval step is what makes it RAG).

## Functions

1. [`loadModel()`](/sdk/reference/api#loadmodel) (with `modelType: "embeddings"`)
2. [`embed()`](/sdk/reference/api#embed) — generate vectors
3. Use any combination of the RAG functions below as needed:
   - [`ragChunk()`](/sdk/reference/api#ragchunk) — chunk documents
   - [`ragIngest()`](/sdk/reference/api#ragingest) — embed and store (requires model)
   - [`ragSaveEmbeddings()`](/sdk/reference/api#ragsaveembeddings) — save pre-computed vectors
   - [`ragSearch()`](/sdk/reference/api#ragsearch) — query similar documents (requires model)
   - [`ragReindex()`](/sdk/reference/api#ragreindex) — optimize search index
   - [`ragDeleteEmbeddings()`](/sdk/reference/api#ragdeleteembeddings) — remove documents
   - [`ragListWorkspaces()`](/sdk/reference/api#raglistworkspaces) — list workspaces
   - [`ragCloseWorkspace()`](/sdk/reference/api#ragcloseworkspace) — release resources
   - [`ragDeleteWorkspace()`](/sdk/reference/api#ragdeleteworkspace) — delete workspace and data
   - [`createVectorIndex()`](/sdk/reference/api#createvectorindex) — build a TurboVec index over your own documents
   - [`loadVectorIndex()`](/sdk/reference/api#loadvectorindex) — reopen a saved TurboVec index
4. [`unloadModel()`](/sdk/reference/api#unloadmodel)

For how to use each function, see [SDK — API reference](/sdk/reference/api/).

## Pipeline

Create your RAG pipeline using [text embeddings](/sdk/ai-capabilities/text-embeddings), the functions above, and [completion](/sdk/ai-capabilities/text-generation).

Regarding vector storage, you may use:
- **External vector DB:** use [`embed()`](/sdk/reference/api#embed) to generate vectors and store them wherever you want (e.g., MongoDB, LanceDB, ChromaDB, SQLite-Vector). Choose this when you need custom persistence, filtering, or integration with an existing database.
- **Built-in TurboVec index with your own document store:** use [`embed()`](/sdk/reference/api#embed) for vectors and [`createVectorIndex()`](/sdk/reference/api#createvectorindex) for on-device nearest-neighbour search. QVAC indexes the vectors; your documents stay in whatever store you already have, and results come back as the ids you assigned. Snapshots can be saved and reopened with [`loadVectorIndex()`](/sdk/reference/api#loadvectorindex).
- **Built-in vector store:** use the RAG workspace functions ([`ragIngest()`](/sdk/reference/api#ragingest), [`ragSearch()`](/sdk/reference/api#ragsearch), etc.). QVAC persists the vectors for you, so this is the simplest path.

<Callout type="warn">
**Built-in vector store is not production grade** and is intended for prototypes only. For production workloads, use one of the external vector DB paths shown below (MongoDB, SQLite, LanceDB, Chroma, etc.).
</Callout>

<Callout type="info">
**Important:** when using an external vector DB, make sure its schema matches the embedding dimensionality produced by your model (e.g., GTE Large embeddings used in the example are 1024‑dimensional).
</Callout>

### External vector DB

#### MongoDB

This example needs two things the SDK does not provide: a MongoDB driver, and a deployment with Atlas Vector Search. Install the driver for the language you are using — `npm i "mongodb@^7.5.0"` for JavaScript and TypeScript, or `pip install "pymongo>=4.13"` for Python. Those are the versions these docs are tested against.

One way to get a deployment is the Atlas local container:

```bash
docker run -p 27017:27017 --name atlas-local mongodb/mongodb-atlas-local
```

The script connects to `mongodb://localhost:27017/?directConnection=true`; edit that connection string if your deployment lives elsewhere.

#### SQLite

This example needs the vector extension for SQLite, which arrives differently per language. JavaScript and TypeScript use a SQLite WASM build that has the extension compiled in; Python uses the standard library's `sqlite3` module and loads the extension from a prebuilt binary. Install the one for the language you are using:

```bash
# JavaScript and TypeScript
npm i "@sqliteai/sqlite-wasm@3.50.4-sync.0.8.30-vector.0.9.23"

# Python
pip install "sqliteai-vector>=1.1"
```

Those are the versions these docs are tested against. Loading an extension also needs a Python configured with `--enable-loadable-sqlite-extensions`. Most distribution and python.org builds are; `pyenv`'s default build is not, and no package you install changes that — pass `-p` to `virtualenv` (or `--python` to `uv venv`) to base the environment on an interpreter that qualifies. The example checks before it starts and tells you if yours does not. The database is in-memory, so there is nothing else to set up.
