## Overview

The Python SDK (`tetherto-qvac-sdk` on PyPI) is the Python client for QVAC.
It is asyncio-native, drives the worker over `bare-rpc`, and exposes every
QVAC capability through a typed API.

## Requirements

- Python `>= 3.10`
- Node.js `>= v22.17` (to host the worker)

For host-level requirements (OS versions, GPU drivers, Vulkan runtime), see [System requirements](/sdk/system-requirements).

## Install

<Steps>
<Step>
Install the package:

```bash
pip install "tetherto-qvac-sdk"
```

Optional extras: `vla`, `notebook`.
</Step>

<Step>
Install the worker:

```bash
python -m tetherto.qvac_sdk install-worker
```

`Client()` finds it automatically after this. To override the location, set `QVAC_WORKER_PATH` or pass `worker_path=` to `Client()`.
</Step>
</Steps>

## Running examples

Follow these instructions to run any example in this documentation:
- All examples are self-contained, runnable Python scripts. Use the `qvac-examples-py` workspace created in this quickstart to store and run them as you explore this documentation.
- Run each example with Python `>= 3.10`, inside the virtualenv where you installed `tetherto-qvac-sdk`.
- More examples can be found in the [Python SDK examples directory](https://github.com/tetherto/qvac/tree/main/packages/sdk-python/examples).

### RPC servers

Serving requires `@qvac/ggml-rpc-server` and a custom worker. In your examples workspace, install the JavaScript SDK and native server package. Replace `<version>` with the version of your installed `tetherto-qvac-sdk` package so the client and worker use the same contract:

```bash
npm install "@qvac/sdk@<version>" @qvac/ggml-rpc-server
```

Create `qvac.config.json` with the server provider:

```json
{
  "rpcServerProvider": "@qvac/sdk/ggml-rpc-server/provider"
}
```

Build the worker:

```bash
npx qvac bundle sdk
```

Python's `Client()` does not automatically select the generated `qvac/worker.entry.mjs`. Set `QVAC_WORKER_PATH` when running the serving example, or pass that path as `worker_path=` to `Client()`:

```bash
QVAC_WORKER_PATH=./qvac/worker.entry.mjs python rpc_servers.py serve <private-ipv4> <topic>
```

Replace `<private-ipv4>` and `<topic>` with your server's private IPv4 address and shared discovery topic. Discovery uses the default worker and does not require the server provider:

```bash
python rpc_servers.py discover <topic>
```

Save the following script as `rpc_servers.py`. It serves an RPC endpoint or discovers endpoints on a shared topic and prints their device aliases and server RDMA availability:

## Configuration

Pass the config to `Client()`:

```python
async with Client(config={"cacheDirectory": "/data/qvac-models"}) as client:
    ...
```

`QVAC_CACHE_DIR` is a shortcut that sets `cacheDirectory` without code.

See [Configuration](/sdk/configuration) for options and schema.

## Notebook / data science (Jupyter)

For notebooks and REPLs, `tetherto.qvac_sdk.notebook.SyncClient` is a synchronous facade over `Client`: every call is a plain blocking call (no `await`), returns numpy/pandas-native data, and streams completions live into the cell.

Install the `notebook` extra:

```bash
pip install "tetherto-qvac-sdk[notebook]"
```

## API reference

Everything you normally need is imported flat from `tetherto.qvac_sdk`; model constants live in `tetherto.qvac_sdk.models`.

| Group | Names |
| --- | --- |
| Client | `Client` (`client.transport` is passed to every call) |
| Ergonomic wrappers | `load_model`, `unload_model`, `completion`, `translate`, `cancel`, `delete_cache`, `invoke_plugin`, `invoke_plugin_stream`, `model_registry_list` / `_search` / `_get_model` |
| Result types | `CompletionRun` (`.events`, `.final`), `CompletionFinal`, `ToolCall`, `TranslateRun` |
| Generated methods | `embed`, `transcribe`, `text_to_speech`, `ocr_stream`, `diffusion_stream`, `classify`, `get_model_info`, `download_asset`, … (each takes a typed request model) |
| RPC server methods | `start_rpc_server`, `stop_rpc_server`, `discover_rpc_servers` from `tetherto.qvac_sdk.methods`, with typed requests from `tetherto.qvac_sdk.schemas`; discovery returns a response with `.servers` |
| Models & enums | `LoadModelRequest`, `ModelType`, … (also in `tetherto.qvac_sdk.schemas`) |
| Errors | `QvacError`, `RPCError`, `InferenceCancelledError`, `ContextOverflowError`, … |
| Logging / VLA | `logging_stream`, `subscribe_server_logs`, `SDK_LOG_ID`; `vla`, `vla_hparams`, `vla_preprocess_image`, `vla_pad_state` |
| Notebook | `tetherto.qvac_sdk.notebook.SyncClient` — synchronous, numpy/pandas returns, live in-cell streaming |

See [API reference](/sdk/reference/api) for the JS/TS surface; the Python API is generated from the same contract.

The JS/TS `getLogger` and `profiler` facades are intentionally not ported — Python uses the standard library [`logging`](https://docs.python.org/3/library/logging.html) module and the per-call `profiled_call` (`tetherto.qvac_sdk.profiling`) instead. See the [Logging](/sdk/runtime/logging) and [Profiler](/sdk/runtime/profiler) pages.
