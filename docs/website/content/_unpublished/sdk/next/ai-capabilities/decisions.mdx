## Overview

Decisions use [`@qvac/decision-ggml`](https://github.com/tetherto/qvac/tree/main/packages/decision-ggml), which runs upstream llama.cpp decision models (Laya, openjev, lev, kev, clef and other types with `<arch>.decision.type` metadata) on the Fabric LLM inference engine. Load a decision model using `modelType: 'llamacpp-decision'` and `modelConfig: { device: 'cpu' }` or `{ device: 'gpu' }`.

[`decide()`](/sdk/reference/api#decide) answers typed questions about a state. Pass `state` for one result, or `states` for an array of results in input order. A state can be text, a number, a boolean, structured JSON, or a conversation array. Top-level `null` is not accepted.

The result contains `answers`, keyed by your question IDs, and `usage` with `inputTokens` and `outputTokens`. Decisions return one aggregate result without a token stream.

## Functions

Use the following sequence of function calls:

1. [`loadModel()`](/sdk/reference/api#loadmodel)
2. [`decide()`](/sdk/reference/api#decide)
3. [`unloadModel()`](/sdk/reference/api#unloadmodel)

For how to use each function, see [SDK — API reference](/sdk/reference/api/).

## Models

Use an upstream llama.cpp decision model in GGUF format. Pass a local GGUF path or another model source supported by [`loadModel()`](/sdk/reference/api#loadmodel) with explicit `modelType: 'llamacpp-decision'`. A GGUF without decision metadata, such as an embedding-only model, fails to load. For checkpoints split into multiple GGUF files, see [Sharded models](/sdk/models/sharded-models).

Laya checkpoints run in upstream format, converted from their Hugging Face checkpoints with `convert_hf_to_gguf.py`. Fabric-format Laya files (`general.architecture` `laya`) do not load. The `LAYA_*` registry constants still point at Fabric-format files; they move to the upstream-format conversions before release.

## Questions

Each entry in `questions` has a `type` and `instructions`:

- `choice` selects a label from `criteria`, which can be an array of labels or an object mapping labels to descriptions. The answer contains `choice`, a probability per label, and `confidence`. Array values must stay distinct as text: `[true, 'true']` or `[1, '1']` is rejected; use an object with distinct keys. Answers return the original value.
- `score` estimates an ordinal level from `criteria`, 2 to 10 descriptions ordered from lowest to highest. The answer contains the expected `score`, a `legend`, probabilities, and `confidence`.
- `noul` answers a statement. The answer contains `noul`; optional `criteria` describe the true and false options. A model may answer `noul` with something other than a probability: lev returns an expected rating from 0 to 1. Set `requireProbability: true` to have such a model reject the request instead. Only some models report a `confidence` for `noul` answers.

States, instructions and descriptions may nest at most 128 levels deep.

The load options are `device`, `gpu_layers`, `batch_size`, `threads`, `verbosity`, and `openclCacheDir` (Android).

## Cancellation and concurrency

The promise returned by [`decide()`](/sdk/reference/api#decide) exposes `requestId` before you await it. Pass that ID to [`cancel()`](/sdk/reference/api#cancel) to interrupt the request. Its promise rejects with `InferenceCancelledError` after the native response settles.

Each loaded model runs one decision request at a time. Concurrent calls wait in a FIFO queue with up to 64 waiting requests per model. When the queue is full, additional calls reject with `RequestRejectedByPolicyError` without affecting active or queued requests. Cancelling a queued call by `requestId` rejects it with `InferenceCancelledError` before native work starts and leaves the active request running. Use `states` to evaluate several states in one request. See [Cancellation](/sdk/runtime/cancellation) for broad cancellation by model ID.
