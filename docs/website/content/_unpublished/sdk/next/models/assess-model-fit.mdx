## Overview

[`assessModelFit()`](/sdk/reference/api#assessmodelfit) answers one question before anything is downloaded: do these models fit in this device's memory when loaded together? For every model it runs the engine's own fitter, against the model where it is already on disk and otherwise against the registry's weightless description of it, tens of KB, the tensor list with no data section. Each fitter reports the memory its load takes on each device. The SDK sums that memory per device and compares the totals against what is free.

It is **advisory**. It never downloads weights or loads a model, and it does not block [`loadModel()`](/sdk/reference/api#loadmodel), reserve memory, pick a model for you, or make any claim about speed.

## Functions

1. [`assessModelFit()`](/sdk/reference/api#assessmodelfit) — describe the loads you are considering, as `loadModel()` takes them.
2. [`downloadAsset()`](/sdk/reference/api#downloadasset) or [`loadModel()`](/sdk/reference/api#loadmodel) — fetch whichever model you picked.

For how to use each function, see [SDK — API reference](/sdk/reference/api/).

## Parameters

```ts
assessModelFit({
  models: [
    {
      modelSrc: QWEN3_8B_INST_Q4_K_M,
      modelType: "llamacpp-completion",
      modelConfig: { ctx_size: 8192 },
    },
  ],
});
```

### `models`

The models, at least one, assessed as if loaded at the same time. Each takes the same parameters as [`loadModel()`](/sdk/reference/api#loadmodel):

- `modelSrc` — the model, as `loadModel()` takes it. A catalog constant resolves to the registry's weightless description of the model; a path already on disk is read directly.
- `modelType` — optional. The engine that would run the load, inferred from `modelSrc` when omitted, as `loadModel()` infers it. Required only where the source names no engine.
- `modelConfig` — optional. The config `loadModel()` would be given, including the companion model sources a compound load needs.

The engine's own plugin resolves that config, so the settings the fitter reads are the ones the load would run with, and the same object can be handed to `loadModel()` afterwards.

Two fit-only fields describe a workload the load itself does not carry: `transcriptionWorkload` for MOSS-Transcribe and `ttsWorkload` for MOSS-TTS/TTSD and MOSS-SoundEffect.

## Returns

```ts
{
  verdict: "fits" | "does-not-fit" | "unknown",
  pools: [{ id, unified, usedBytes, freeBytes?, totalBytes? }],
  models: [
    {
      status: "fits" | "does-not-fit" | "unknown",
      devices: [{ id, name, unified, usedBytes, freeBytes?, totalBytes? }],
      stats: { ctxSize, gpuLayers } | {},
    },
  ],
}
```

### `verdict`

The verdict for every model loaded together. For a single model it is that model's `status`, with the engine's own margin applied by its fitter. For several models:

| Verdict | Meaning |
| --- | --- |
| `fits` | Every model's fitter reached a verdict, and on every device the summed memory is within 90% of what is free. |
| `does-not-fit` | A fitter projects its load will not fit, or on some device the summed memory exceeds 90% of what is free. |
| `unknown` | A model got no verdict, or a device reported no free memory. |

`does-not-fit` wins over `unknown`: when one model is `unknown` and another overflows a device, the set does not fit.

Devices that share memory with the host, the CPU itself, an integrated GPU, Apple's Metal GPU, Android's OpenCL GPU and any device that reports no memory of its own, are counted as one pool against the host's free memory. On iOS the host's free memory is capped at the app's own limit. A discrete GPU is its own pool.

### `pools`

The memory pools the verdict was judged on: `host` for the host's memory, and one pool per discrete GPU, keyed by its `id`. Each carries `usedBytes`, what the set takes from it, and `freeBytes` and `totalBytes`, the lowest figures reported for it. `unified` is true for the host pool.

### `models`

One entry per model, in input order: the engine addon's own fit result.

- `status` — that model's verdict alone.
- `devices` — one row per device the load uses, the host last. `id` is the PCI bus ID where the backend reports one and the device name otherwise, so the same GPU matches across engines. `name` is the backend's device name, such as `CPU`, `CUDA0` or `MTL0`. `unified` marks memory the host owns. `usedBytes` is what the load takes there; `freeBytes` and `totalBytes` are what the device reported.
- `stats` — for a llama.cpp model with a verdict, the context size and GPU layers the load resolves to: the ones the fitter settled on when it fits, the ones the load asked for when it does not. Empty for every other model.

A model the SDK cannot size has `status: "unknown"`, no rows and empty `stats`.

### Errors

A load that [`loadModel()`](/sdk/reference/api#loadmodel) would refuse throws the same error: no plugin for the model type, a config the plugin refuses, or the engine fitter rejecting the load, such as a model it cannot read. A load that would start but cannot be sized is `unknown`.

## Where verdicts are available

A verdict exists wherever the engine's own fitter runs: every platform that ships that engine's addon, mobile included, for a model on disk or with a published registry description.

The fitter covers `llamacpp-completion`, `llamacpp-embedding`, `whispercpp-transcription`, `parakeet-transcription`, `moss-transcribe`, `bci-whispercpp-transcription`, `tts-ggml`, `audiogen-ggml`, `sdcpp-generation`, `ggml-ocr` and `nmtcpp-translation`. The translation fitter reads the model and vocabulary files themselves, so it answers for files on disk only. OCR sizes its weights alone, leaving the memory an image needs uncounted. For `sdcpp-generation` the fitter covers image generation with any configured ESRGAN `upscaler`, video, standalone `mode: 'upscale'` and `mode: 'world'`; a world load needs a pre-built `sceneSrc`, and `world.fitSteps` sets how many walk steps the fit covers.

Everything else is `unknown`: `onnx-tts`, `ggml-vla` and `ggml-classification`, a translation model not yet downloaded, MOSS-Speech, a TTS load with a LavaSR enhancer or denoiser, a diffusion world load without a `sceneSrc`, a load naming an ESRGAN checkpoint not yet downloaded, a diffusion load pinned to one device, split models, multimodal completion loads naming a projection model, and any model whose registry description cannot be fetched within the [`fitStubBudgetMs`](/sdk/configuration) budget.

## Load-time check

Once the weights are on disk, [`loadModel()`](/sdk/reference/api#loadmodel) runs the same engine fitter against the real files and the resolved load settings before it loads, with the same calculation. The fitter runs in the SDK's worker process on every platform.

A fit that does not finish, because the fitter crashed or the process quit, is retried on the next load with the same settings. A second one in a row resolves to `unknown` for a while. A fitter that does not return within 30 seconds resolves to `unknown` and the load continues. A fitter that rejects the load is logged and resolves to `unknown`, so the check never fails a load on its own. Cancelling a load during its fit stops it before the model loads. Verdicts appear on the SDK log stream as `[advisory-fit:…]` lines.

[`getLoadedModelInfo()`](/sdk/reference/api#getloadedmodelinfo) returns the outcome as `fitProbe`, in the same shape as an `assessModelFit()` result with one model: `verdict`, `pools`, and `models` holding the engine's own fit result.

### `modelFitPolicy`

Pass it to `loadModel()` for one load, or set it in the engine config for every load.

- `log` (default) — the verdict is reported and the load proceeds.
- `refuse` — a load the fitter projects will not fit is rejected with `MODEL_FIT_REFUSED` before the addon allocates anything. Only `does-not-fit` refuses; `unknown` never does, so a load is never refused for lack of evidence.
- `off` — the check does not run, and `fitProbe` is then absent.

```typescript
await loadModel({
  modelSrc: QWEN3_8B_INST_Q4_K_M,
  modelType: 'llamacpp-completion',
  modelConfig: { ctx_size: 8192 },
  modelFitPolicy: 'refuse'
})
```
