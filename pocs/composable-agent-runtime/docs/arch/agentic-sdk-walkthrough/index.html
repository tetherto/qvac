01 Story

Why the split exists

The QIP pushes infrastructure out of the normal app path. Developers can start from Assistant, then intentionally drop to lower layers when they need state, execution, framework primitives, or inference directly.

Normal path

@qvac/assistant starts and connects Sync and Harness, applies defaults, propagates config, and exposes one lifecycle.

Escape hatches

Applications can consume Sync, Harness, Agents, or SDK directly. These paths are supported choices, not prerequisites for basic use.

Package proof

The PoC exists to validate package and runtime boundaries. A blurred boundary is a finding, not a local implementation detail.

02 Packages

Ownership stays narrow

Each package owns a crisp responsibility. The boundaries keep Sync and Harness as siblings, keep SDK focused on inference, and keep reusable mechanisms out of product policy.

@qvac/assistant

Application facade, root lifecycle, typed client creation, default storage, pairing and device-management flow.

@qvac/sync

Cryptographic device identity, mesh membership, replicated state, durable work, watches, and migrations.

@qvac/harness

Ready-to-run execution: agent scheduling, model/tool loop, approvals, state backend selection, sandboxing, and SDK child supervision.

@qvac/agents

Transport-free primitives: agents, tools, guards, approvals, turn budgets, events, and checkpoints.

@qvac/sdk

Inference via its public client/worker path, model lifecycle, plugins, downloads, and cache ownership.

@qvac/supervisor and @qvac/config

Lifecycle mechanics and immutable config snapshot mechanics. Neither owns product policy or concrete runtime keys.

Application-owned skills: concrete weather, Obsidian, image, coding, OAuth, git, or terminal behavior belongs in applications. Harness exposes worker authoring kits under @qvac/harness/skill-host and @qvac/harness/skill-sandbox only.

03 Runtime

Separate restart domains

Sync, Harness, and SDK each own their worker artifacts and runtime compatibility. Assistant composes the normal path; direct consumers become the root lifecycle owner for the package they use.

1

State ready

Local Sync storage and stable device identity are available. Peers and DHT reachability do not block this gate.

2

Execution ready

assistant.ready() means Harness is compatible and connected to the injected durable state input.

3

Model ready

Model preparation is lazy and keyed by model. SDK or model failure does not make local state unavailable.

Dependency direction

Assistant composes Sync and Harness. Harness uses Agents and SDK. Sync never depends on Harness, Agents, or SDK. Harness receives durable state as injected structure, not as a package dependency. SDK never depends on Sync, Harness, or Agents. Supervisor and Config depend on no product package.

What developers touch

The public surface keeps the common Assistant path small while preserving direct package entry points for lower-level consumers.

packages/assistant/examples/assistant-inbox.tsrun stream
async function runTask(
  assistant: AssistantFacade,
  inbox: ReturnType<typeof createInboxRepository>,
  task: InboxTask,
  signal: AbortSignal
) {
  let output = ''
  await inbox.update({ id: task.id, status: 'running', result: null })

  for await (const event of assistant.run({
    agentId: DEFAULT_AGENT_ID,
    runId: runIdFor(task.id),
    input: task.input,
    signal
  })) {
    if (event.type === 'content') {
      output += event.text ?? ''
      await inbox.update({ id: task.id, status: 'running', result: output })
    } else if (event.type === 'error') {
      throw new Error(event.message)
    }
  }
}

05 Delegation

Durable task routing, not inference proxying

SDK-native delegate and provide are retired by the target architecture. Cross-device work moves through Sync-backed durable state and is executed by a target Harness through its own SDK runtime.

Context-carrying

The run request includes the transportable context needed by the target Harness. The SDK only sees inference work.

Disconnect-tolerant

Live streams can overlay durable state, but the durable record is the source of truth for progress and terminal results.

Explicit policy

Paired identity is not blanket authorization. Harness applies execution policy for models, tools, capabilities, and expiry.

Guarantee note: this is the architecture for durable routing, not a promise of exactly-once tool effects. Duplicate handling, fencing, and idempotency remain explicit execution-policy concerns.

06 Failure Model

Supervision without hidden replay

Supervisor restarts and reconnects runtime components. It does not decide whether interrupted work is safe to replay. That policy remains in Harness, Agents, and Sync.

SDK runtime crashes

Harness reports an inference failure, restarts SDK under policy, and preserves its own process plus Sync state.

Harness crashes

Assistant keeps Sync alive, restarts Harness, reconnects its client, and recovers only from committed checkpoints.

Sync crashes

Assistant restarts Sync. Harness must pause durable commits and must not silently downgrade a durable run to memory.

Repeated crash loop

Supervisor stops retrying, marks the component failed, and returns a human-readable error with diagnostic context.

Important boundary note: side-effecting tools are not automatically replayed. Stable operation IDs, checkpoints, claim rules, and idempotency policy must decide whether recovery marks work interrupted or attempts a retry.
