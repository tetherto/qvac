# Agent Configuration Unification

**Status:** Implemented on `feature-agent-config-unification`
**Scope:** Cursor, Claude Code, and Codex

## Decision

Use shared content with thin host adapters:

| Concern | Canonical location | Compatibility layer |
|---|---|---|
| Repository skills | `.agents/skills/` | Claude entries under `.claude/skills/` generated by `/setup claude` |
| Repository instructions | `AGENTS.md` and nearest scoped `AGENTS.md` | `CLAUDE.md` imports root `AGENTS.md`; Cursor `.mdc` selectors point to scoped guidance |
| Durable technical guidance | Existing READMEs/docs, plus concise owning-package docs where no source existed | None |
| Host-specific skill policy | Inside each skill package | `agents/openai.yaml` for Codex; supported frontmatter for other hosts |
| Cursor path selection | Shared instructions or docs | Small `.cursor/rules/*.mdc` files retain Cursor `globs` and always-apply behavior |

Do not remove `.cursor/` or `.claude/` entirely. The hosts share the Agent Skills
format, but they do not share every discovery path, rule engine, hook, permission,
subagent, or UI capability.

## Compatibility distinctions

- Cursor and Codex discover project skills under `.agents/skills`.
- Claude Code documents project skill discovery under `.claude/skills`, so it
  still needs an adapter.
- Codex loads `AGENTS.md`; Claude Code loads `CLAUDE.md` and supports importing
  `AGENTS.md`; Cursor's `.mdc` rules add glob-based context selection that the
  shared file does not express.
- Codex invocation policy is stored per skill at
  `.agents/skills/<skill-name>/agents/openai.yaml`.

The Claude adapter uses per-skill symlinks on Unix:

```text
.claude/skills/<name> -> ../../.agents/skills/<name>
```

On Windows, `/setup claude` creates ignored copies because ordinary Git and
developer environments do not reliably permit symlink creation. The setup script
records only entries it generated and verifies ownership before replacing them.
It automatically migrates exact per-skill links to the former `.cursor/skills`
tree, but stops with recovery instructions for shared-directory links and other
ambiguous collisions. The tracked bootstrap and unrelated local skills are left
alone.

## Implemented changes

- Reconciled 34 repository skills under `.agents/skills` and removed the duplicate
  tracked `.cursor/skills` tree.
- Preserved all 19 manual-only skills with
  `policy.allow_implicit_invocation: false` in their per-skill Codex metadata.
- Updated scripts, workflows, and documentation to use the canonical skill paths.
- Kept `.claude/skills/setup` as a tracked bootstrap; `/setup claude` creates the
  remaining local Claude compatibility entries through the root-owned
  `scripts/agent-setup.sh`.
- Kept the `packages/ocr-ggml/.agent` pilot behind its explicit package setup
  command. General setup does not install OCR conduct, knowledge, agents,
  settings, or package skills; broader adoption can follow usability validation.
- Reduced root `AGENTS.md` to stable operating policy and pointers to authoritative
  repository sources. Personal defaults remain in `~/.codex/AGENTS.md`; no global
  or repository override file is added.
- Reduced `CLAUDE.md` to the shared import and Claude-specific setup guidance.
- Reduced Cursor rules to thin selectors or genuine Cursor-only guardrails. Stable
  package guidance now lives in nearest scoped `AGENTS.md` files; detailed or
  volatile facts stay in source, package READMEs, workflows, and owning docs.
- Added `scripts/ci/validate-agent-config.mjs` and wired it into the existing shared
  CI workflow to detect skill metadata, link, adapter, and legacy-duplication drift.

Documentation maintenance follows one repository-wide rule: rewrite the owning
document in place and remove obsolete text. Changelogs, migration records, and
ADR/QIP supersession history remain valid historical exceptions.

## Delivery plan

Deliver the branch as one atomic PR. Splitting skills, shared instructions, and
rule cleanup into separate PRs would create intermediate states in which one host
sees stale or duplicated configuration. Review the single PR in three passes:

1. Canonical skills and Claude adapter.
2. Root and scoped instructions.
3. Cursor rule reduction and durable-doc relocation.

Before handoff, run:

```bash
node --check scripts/ci/validate-agent-config.mjs
node scripts/ci/validate-agent-config.mjs
bash -n scripts/agent-setup.sh
bash -n packages/ocr-ggml/.agent/setup.sh
```

Also exercise `/setup claude` twice in a clean temporary checkout and run the
validator there with `--claude-mirror`. Verify the Windows copy fallback on a
Windows environment when one is available. Do not commit, push, publish, or create
the PR until the user explicitly requests it.

## Known host-runtime check

Cursor also scans `.claude/skills`. Its documentation does not define whether a
canonical skill and a symlink to the same real directory are de-duplicated in the
UI. Filesystem and setup behavior are deterministic, but the installed Cursor
agent could not be used for this runtime check because the environment blocked
external agent access to repository content. Dual-host users can disable **Include
third-party Plugins, Skills, and other configs** in Cursor to suppress Claude
compatibility entries while retaining native `.agents/skills` discovery; that
setting also disables other third-party configuration compatibility.

## Workbench comparison

`/Users/yury/Dev/qvac/wb` uses one real skill tree with host-directory symlinks.
That removes file duplication but aliases Cursor `.mdc` rules into hosts that use
different rule semantics. This implementation keeps the useful symlink pattern for
skills while treating instructions, rules, and host metadata explicitly.
