# Docs scope — what `qv-docs-update` may write

Check every path against this file before writing a patch, and again in the Phase 6 scope gate. A write outside it aborts the run and reverts every patch already applied.

Paths are relative to the monorepo root. `<root>` stands for the documentation root of a software the change touches: the first entry of `paths` in its `docs/website/versions/<slug>.json`, for example `packages/sdk/docs/users`.

## The one line this skill writes

Each software publishes one documentation line per version. A released line is read from the commit its versions file pins; the line the current branch holds is `<root>` in the working tree. On `main` that is the unreleased version, and on a release branch it is that released version. The skill documents the working tree, so it writes `<root>` on the current branch and nothing else. It never edits a versions file, and never writes to another branch.

Lines still held in place under `docs/website/content/docs/<slug>/` predate the migration of their software. They are never written by this skill.

## Writable

```text
<root>/**/*.mdx            hand-written pages, except generated ones
<root>/**/meta.json        navigation: append a new page's slug only
```

In a `meta.json`, append to the end of the `pages` array. Never reorder, rewrite, or remove an entry.

## Written only by a tool

```text
<root>/_generated/**                 the software's data scripts in docs/website (`docs:*-api`)
<root>/api-bindings.lock.json        `npm run docs:lock`
generated pages under <root>         the data scripts; a generated page starts with
                                     {/* Generated by … Do not edit. */}
the software's contract              its own generator (for the SDK, `contract:export`)
```

Running these tools is part of the skill. Editing their output by hand is a scope violation: the next run overwrites it, and the `--check` gates fail on it.

## Read-only

```text
packages/**                except the two lists above: source and examples are the developer's
docs/website/**            site code, versions files, and every collection's content
```

If a source file is wrong — an example that no longer compiles, a description that contradicts the code — report it and stop.

A page that belongs in a listing outside `<root>`, such as the Ecosystem overview, is named in the report for the documentation owner, never edited.

## Routing consequence

A candidate page outside the writable scope is discarded, never rewritten. Record the discard in the report with its reason, so a recurring near-miss is visible.
