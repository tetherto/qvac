# QVAC Transcription Whispercpp Addon v0.5.0 Release Notes

This release migrates the Whispercpp addon to the `qvac-lib-inference-addon-cpp` 1.x runtime architecture and hardens job lifecycle behavior across JS/native boundaries. Because the package moved off the removed legacy templated addon API, this is released as a backward-incompatible minor bump.

## Changes

### Migrate native addon to addon-cpp 1.x

The addon now uses the `IModel`-based runtime with `AddonJs`/`AddonCpp` factories and `createInstance`/`runJob` execution flow. Legacy templated addon and js-interface wiring were removed.

### Improve runtime parity and lifecycle handling

Cancellation, output propagation, and run-state transitions were hardened to match expected production behavior under the addon-cpp 1.x job runner. C++ and JS parity coverage was expanded, including dedicated `AddonCpp` tests.

### Standardize runtime errors for new paths

New busy-run and invalid-audio-input paths now use package error codes in `lib/error.js` instead of ad-hoc error strings.

## Backward Compatibility

The high-level `TranscriptionWhispercpp` JavaScript API remains compatible for standard package consumers.

Direct consumers of removed legacy native addon internals (templated addon/js-interface paths) must migrate to the addon-cpp 1.x runtime model introduced in this release.
