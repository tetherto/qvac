Stops an RPC server started with [`startRpcServer`](/sdk/reference/api/startRpcServer). It withdraws the server's discovery announcement, if any, then waits for the native server to stop. The wait has no deadline. Unload the models that use the endpoint before you call it. See [RPC servers](/sdk/p2p-capabilities/rpc-servers).

## Signature

```ts
function stopRpcServer(options: StopRpcServerOptions): Promise<void>;
```

## Parameters

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `options` | The server to stop. | [`StopRpcServerOptions`](#stoprpcserveroptions) | Yes |

### `StopRpcServerOptions`

| Option | Description | Type | Required |
| --- | --- | --- | --- |
| `serverId` | ID of the server, as `startRpcServer` returned it. | `string` | Yes |

## Returns

A promise that resolves with no value once the server has stopped. When the stop fails, the server stays registered, and you can call `stopRpcServer` again to retry.

## Throws

| Error | When |
| --- | --- |
| `RequestValidationFailedError` | `serverId` is empty. |
| `RpcServerOperationError` | No running server has this `serverId` in the worker. |
| `RpcServerOperationError` | Withdrawing the announcement or stopping the native server fails. The `details` field carries the reason. |
| `QvacErrorBase` | The worker answers with an invalid response type. |

## Examples

```ts
import { startRpcServer, stopRpcServer } from "@qvac/sdk";

const server = await startRpcServer();

// ... other workers load models on server.url, then unload them ...

await stopRpcServer({ serverId: server.serverId });
```
