Suspends the SDK runtime: pauses every registered Hyperswarm and Corestore resource and engages the lifecycle gate, so operations other than `suspend()`, [`resume()`](/sdk/reference/api/resume), and [`state()`](/sdk/reference/api/state) fail fast with `LIFECYCLE_OPERATION_BLOCKED` instead of hanging. Call it when the host app moves to the background. The call is idempotent and never blocked by the gate. See [Runtime lifecycle](/sdk/runtime/lifecycle).

Operations already running when `suspend()` is called continue as follows:

| Operation | During suspend | After `resume()` |
| --- | --- | --- |
| P2P / Hyperdrive download | Stalls | Continues |
| HTTP download | Keeps downloading | — |
| Local native inference, such as `completion()` | Runs to completion | — |

## Signature

```ts
function suspend(): Promise<void>;
```

## Returns

A promise that resolves with no value once the runtime is `"suspended"`. Called while a `resume()` is in progress, it waits for the resume to finish, then suspends.

## Throws

An error written as a code, such as `MODEL_NOT_FOUND`, is not exported as a class: it reaches the caller as an `Error` whose `name` is that code.

| Error | When |
| --- | --- |
| `LIFECYCLE_SUSPEND_FAILED` | One or more resources fail to suspend. The runtime still moves to `"suspended"`, so `resume()` can recover it. |
| `InvalidResponseError` | The worker answers with an unexpected response type. |

## Examples

```ts
import { state, suspend } from "@qvac/sdk";

// Background handler.
await suspend();
console.log(await state()); // "suspended"
```
