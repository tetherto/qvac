Resolves with the hyperparameters of a loaded VLA model and the name of the backend it runs on. Call it before [`vla()`](/sdk/reference/api/vla) to size the image, state, token, and noise buffers, and again after every [`vlaSetEmbodiment()`](/sdk/reference/api/vlaSetEmbodiment). See [VLA](/sdk/ai-capabilities/vla).

## Signature

```ts
function vlaHparams(params: { modelId: string }): Promise<{ hparams: VlaHparams; backendName: string | null }>;
```

## Parameters

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `params.modelId` | ID of a model loaded with `modelType: "vla"` (`"ggml-vla"`). | `string` | Yes |

## Returns

A promise that resolves with:

| Field | Description | Type |
| --- | --- | --- |
| `hparams` | The model's hyperparameters. | [`VlaHparams`](#vlahparams) |
| `backendName` | Human-readable backend name, such as `"CPU"`, `"Vulkan"`, `"Metal"`, or `"OpenCL"`. `null` when the addon has not surfaced one. | `string \| null` |

### `VlaHparams`

| Field | Description | Type |
| --- | --- | --- |
| `chunkSize` | Number of timesteps in an action chunk. | `number` |
| `actionDim` | Dimension of each produced action vector. `vla()` returns `chunkSize * actionDim` actions. | `number` |
| `maxActionDim` | Action dimension used to size the `noise` prior: `chunkSize * maxActionDim`. | `number` |
| `maxStateDim` | Length of the `state` buffer for continuous-state models. | `number` |
| `tokenizerMaxLength` | Length of the `tokens` and `mask` buffers. GR00T reports `0`: its prompt length is fixed by the model. | `number` |
| `visionImageSize` | Side of each preprocessed image; `imgWidth` and `imgHeight` must equal it. | `number` |
| `numCameras` | Number of camera views the model expects: 2 for SmolVLA and GR00T, 3 for π₀.₅. Pass exactly this many entries in `images`. Older addon builds may omit it. | `number` |
| `stateInputMode` | How the robot state is consumed. `"continuous"` (SmolVLA, GR00T): an in-model linear layer projects the `state` buffer. `"discrete"` (π₀.₅): the state is tokenized into the prompt, and `state` is ignored. Older addon builds may omit it. | `"continuous" \| "discrete"` |
| `imageInputMode` | How images are supplied. `"pixels"` (SmolVLA, π₀.₅): each `images` entry is a `3 * imgWidth * imgHeight` CHW plane from `vlaPreprocessImage()`. `"patches"` (GR00T): each entry is a pre-patchified buffer of length `imagePatchElems`. Older addon builds may omit it. | `"pixels" \| "patches"` |
| `imagePatchElems` | For patch-input models, the exact length of each `images` entry. Absent for pixel-input models. | `number` |
| `selectedEmbodimentTag` | GR00T only: the embodiment tag resolved at load or after `vlaSetEmbodiment()`. Absent for SmolVLA and π₀.₅. A single-embodiment GGUF also reports its baked tag and still rejects `vlaSetEmbodiment()`. | `string` |
| `selectedEmbodimentCatId` | The resolved embodiment's numeric `cat_id`, from 0 to 31: pass it back to select the same embodiment by ID. Absent when no embodiment was resolved (SmolVLA, π₀.₅). | `number` |

## Examples

```ts
const { hparams, backendName } = await vlaHparams({ modelId });
console.log(backendName ?? "(unknown)", hparams.numCameras, hparams.imageInputMode);

const tokens = new Int32Array(hparams.tokenizerMaxLength);
const noise = new Float32Array(hparams.chunkSize * hparams.maxActionDim);
```
