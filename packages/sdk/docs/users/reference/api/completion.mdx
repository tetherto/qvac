title: completion
titleStyle: code
description: Generates a response from a loaded LLM for a conversation history, as a stream of typed events and an aggregated final result.
binds:
  - fn:completion
---

Runs one generation turn on a loaded LLM. It takes the conversation `history` and, optionally, tools, MCP clients, sampling parameters, a structured-output constraint, and a KV cache key. It returns a [`CompletionRun`](#returns) synchronously: an ordered stream of typed events plus promises that settle when generation ends. Use it for chat, tool calling, multimodal prompts, and structured output. To run several prompts in one call, use [`batchCompletion()`](/sdk/reference/api/batchCompletion).

## Signature

```ts
function completion(params: CompletionParams): CompletionRun;
```

## Parameters

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `params` | The conversation, the model that answers it, and the generation options. | [`CompletionParams`](#completionparams) | Yes |

### `CompletionParams`

| Option | Description | Type | Required | Default |
| --- | --- | --- | --- | --- |
| `modelId` | ID of a loaded `llamacpp-completion` (`llm`) model, as [`loadModel()`](/sdk/reference/api/loadModel) returned it. | `string` | Yes | — |
| `history` | The conversation sent to the model, oldest message first. The model generates the next turn from the full sequence. | [`HistoryMessage`](#historymessage)`[]` | Yes | — |
| `stream` | `true` delivers events as the model produces them. `false` delivers every event at once when generation ends, and leaves `tokenStream` and `toolCallStream` empty. | `boolean` | Yes | — |
| `tools` | Tools the model can call: all full [`Tool`](#tool) objects, or all [`ToolInput`](#toolinput) objects with Zod schemas. Load the model with `modelConfig.tools: true` to enable tool calling. Cannot be combined with a `json_object` or `json_schema` `responseFormat`. | [`Tool`](#tool)`[] \| ` [`ToolInput`](#toolinput)`[]` | No | — |
| `mcp` | MCP clients whose tools are added to the request, listed before `tools`. Their tool calls get an `invoke()` that calls the MCP server. See [MCP](/sdk/ai-capabilities/text-generation#mcp). | [`McpClientInput`](#mcpclientinput)`[]` | No | — |
| `generationParams` | Sampling and tool-choice parameters for this request. | [`GenerationParams`](#generationparams) | No | — |
| `responseFormat` | Structured-output constraint on the answer. Cannot be combined with `tools`. | [`ResponseFormat`](#responseformat) | No | `{ type: "text" }` |
| `kvCache` | KV cache for follow-up turns: `true` lets the SDK derive the cache key from the history, a non-empty string is a cache key you manage, `false` disables caching. See [KV cache](/sdk/ai-capabilities/text-generation#kv-cache). | `boolean \| string` | No | No cache |
| `prefill` | Evaluate the prompt and tools without generating an answer. The run ends with stats, no content, and no tool calls. Requires `kvCache` to be `true` or a non-empty key, and rejects a forced `generationParams.tool_choice` (`"required"` or a tool name). | `boolean` | No | `false` |
| `captureThinking` | Emit the model's reasoning as `thinkingDelta` events, separate from `contentDelta`. Requires a model that frames its thinking output, such as `<think>` blocks. | `boolean` | No | `false` |
| `emitRawDeltas` | Also emit every raw model token as a `rawDelta` event, in addition to the normalized events. | `boolean` | No | `false` |
| `toolDialect` | Tool-call output format to parse. Overrides the dialect detected at load from the model name, then the GGUF `general.architecture`, then `"hermes"`. Set it when detection picks the wrong parser for your model. | `"hermes" \| "pythonic" \| "json" \| "harmony" \| "qwen35" \| "gemma4" \| "dsml"` | No | Detected at load |
| `rpcOptions` | Transport options for this call only. | [`RPCOptions`](#rpcoptions) | No | — |

#### `Tool`

A tool definition in JSON Schema form.

| Field | Description | Type | Required |
| --- | --- | --- | --- |
| `type` | Always `"function"`. | `"function"` | Yes |
| `name` | Tool name the model calls. `tool_search` is reserved when any tool sets `deferLoading`. | `string` | Yes |
| `description` | What the tool does, shown to the model. | `string` | Yes |
| `parameters` | JSON Schema object for the arguments: `type: "object"`, `properties`, and optional `required`. Passed to the model as declared, including nested `properties`, `items`, nullable types, and `anyOf`. | `{ type: "object"; properties: Record<string, object>; required?: string[] }` | Yes |
| `deferLoading` | Keep the parameter schema out of the initial prompt. Only the name and description reach the model, in the catalog of the built-in `tool_search` tool; the schema is added once the model searches for it. See [Deferred tool loading](/sdk/ai-capabilities/text-generation#deferred-tool-loading). | `boolean` | No |
| `group` | Heading the tool is listed under in the deferred catalog, such as a skill or MCP server name. Ignored for tools that are not deferred. | `string` | No |

#### `ToolInput`

A tool definition with a Zod schema. The SDK converts `parameters` to JSON Schema with `z.toJSONSchema`, so nested objects and arrays keep their structure.

| Field | Description | Type | Required |
| --- | --- | --- | --- |
| `name` | Tool name the model calls. | `string` | Yes |
| `description` | What the tool does, shown to the model. | `string` | Yes |
| `parameters` | Zod object schema for the arguments. | `z.ZodObject` | Yes |
| `handler` | Runs the tool. When set, the matching calls in `toolCalls` carry an `invoke()` that calls it with the parsed arguments. | `(args: Record<string, unknown>) => Promise<unknown>` | No |
| `deferLoading` | As in [`Tool`](#tool). | `boolean` | No |
| `group` | As in [`Tool`](#tool). | `string` | No |

#### `McpClientInput`

| Field | Description | Type | Required | Default |
| --- | --- | --- | --- | --- |

| `includeResources` | Add `list_resources` and, when the client has `readResource()`, `read_resource` tools backed by the client's resources. Applies only when the client has `listResources()`. | `boolean` | No | `true` |
| `deferLoading` | Defer every tool this client exposes. See [`Tool`](#tool). | `boolean` | No | `false` |
| `group` | Catalog heading for this client's deferred tools. | `string` | No | — |

#### `GenerationParams`

| Field | Description | Type | Required | Default |
| --- | --- | --- | --- | --- |
| `temp` | Sampling temperature, typically from `0` to `2`. | `number` | No | — |
| `top_p` | Top-p (nucleus) sampling cutoff, from `0` to `1`. | `number` | No | — |
| `top_k` | Top-k sampling: keep only the K most likely tokens. | `number` | No | — |
| `predict` | Maximum tokens to generate. `-1` generates until a stop token, `-2` until the context is full. | `number` | No | Load-time `modelConfig.predict` |
| `seed` | Random seed, for reproducible output. | `number` | No | — |
| `frequency_penalty` | Penalty on tokens by how often they appeared so far. | `number` | No | — |
| `presence_penalty` | Penalty on tokens that already appeared. | `number` | No | — |
| `repeat_penalty` | Penalty on repeated tokens. | `number` | No | — |
| `reasoning_budget` | Reasoning channel budget for this request: `-1` keeps reasoning on, `0` disables it, a positive integer caps it at that many tokens. The load-time value is restored afterwards. | `number` | No | Load-time `reasoning_budget` |
| `tool_choice` | Tool calling for a request that declares `tools`: `"auto"` lets the model decide, `"required"` forces a call, `"none"` keeps the definitions in the prompt but disables the tool-call grammar, and a tool name forces a call to that tool. `"required"` and a tool name are rejected when no tools are declared, and cannot name a deferred tool (force `"tool_search"` instead). A request that cannot honor the choice fails rather than answering in prose. llama.cpp-backed models only. | `string` | No | `"auto"` |
| `parallel_tool_calls` | Allow more than one tool call in one response. `false` keeps one. llama.cpp-backed models only. | `boolean` | No | `true` |

## Returns

A `CompletionRun`, returned synchronously. `events` and `final` are the primary surfaces; `tokenStream`, `toolCallStream`, `text`, `toolCalls`, and `stats` are convenience views derived from the same events.

| Field | Description | Type |
| --- | --- | --- |
| `requestId` | ID of this run, available as soon as `completion()` returns. Pass it to [`cancel({ requestId })`](/sdk/reference/api/cancel) to stop this run without affecting other requests on the model. A cancel only takes effect once the request has begun, so one issued in the same tick may not match. | `string` |
| `events` | Every event of the run, in order. Ends after the `completionDone` event. | `AsyncIterable<`[`CompletionEvent`](#completionevent)`>` |
| `final` | Resolves when the run ends, with the aggregated result. | `Promise<`[`CompletionFinal`](#completionfinal)`>` |
| `tokenStream` | The text of each `contentDelta` event. Empty when `stream` is `false`. | `AsyncGenerator<string>` |
| `toolCallStream` | Each `toolCall` event (`{ type, seq, call }`). Empty when `stream` is `false`. | `AsyncGenerator<{ type: "toolCall"; seq: number; call: ToolCall }>` |
| `text` | Resolves with `final.contentText`. | `Promise<string>` |
| `toolCalls` | Resolves with `final.toolCalls`. | `Promise<`[`ToolCall`](#toolcall)`[]>` |
| `stats` | Resolves with `final.stats`, or `undefined` when the model reported none. | `Promise<`[`CompletionStats`](#completionstats)` \| undefined>` |

### `CompletionEvent`

Every event has a `type` and a `seq`, its zero-based position in the run.

| `type` | Other fields | Emitted |
| --- | --- | --- |
| `"contentDelta"` | `text: string` | For each piece of answer text. |
| `"thinkingDelta"` | `text: string` | For each piece of reasoning text, when `captureThinking` is `true`. |
| `"rawDelta"` | `text: string` | For each raw model token, when `emitRawDeltas` is `true`. |
| `"toolCall"` | `call:` [`ToolCall`](#toolcall) | For each parsed tool call. |
| `"toolError"` | `error:` [`ToolCallError`](#toolcallerror) | For each tool-call region that could not become a tool call. |
| `"completionStats"` | `stats:` [`CompletionStats`](#completionstats) | Once, with the run's performance figures. |
| `"completionDone"` | `stopReason?:` [`StopReason`](#stopreason), `raw?: { fullText: string }`, `error?: { message: string }` | Last. `error` is present only when `stopReason` is `"error"`. |

#### `StopReason`

| Value | Meaning |
| --- | --- |
| `"eos"` | The model finished on its own. |
| `"length"` | The `predict` budget ran out or the context window filled. The output is truncated. |
| `"stopSequence"` | A configured stop sequence ended generation. |
| `"cancelled"` | The run was cancelled. |
| `"error"` | Generation failed mid-stream. Only on the `completionDone` event, never on `final`. |

`stopReason` is absent when the backend reported no specific reason.

### `CompletionFinal`

| Field | Description | Type |
| --- | --- | --- |
| `contentText` | The answer text: every `contentDelta` joined. | `string` |
| `thinkingText` | The reasoning text: every `thinkingDelta` joined. Present only when there was some. | `string` |
| `toolCalls` | Tool calls the model made, in order. | [`ToolCall`](#toolcall)`[]` |
| `toolErrors` | Tool-call regions that could not become a tool call. Present only when there were some. Tells a malformed call apart from no call. | [`ToolCallError`](#toolcallerror)`[]` |
| `stats` | Performance figures, when the model reported them. | [`CompletionStats`](#completionstats) |
| `stopReason` | Why generation stopped. | `"eos" \| "length" \| "stopSequence"` |
| `raw.fullText` | The exact model output, including any reasoning markup. | `string` |
| `cacheableAssistantContent` | With `kvCache: true`: the assistant text to push back into `history` for the next turn, unchanged, so the next call hits the cache. Absent on turns with tool calls, which cannot be auto-cached. | `string` |

#### `ToolCall`

| Field | Description | Type |
| --- | --- | --- |
| `id` | Call ID. Echo it as `toolCallId` on the `tool` message that answers the call. | `string` |
| `name` | Name of the called tool. | `string` |
| `arguments` | Parsed arguments. | `Record<string, unknown>` |
| `raw` | The model's raw text for this call. | `string \| undefined` |
| `invoke` | Runs the call: present when the tool came from a [`ToolInput`](#toolinput) with a `handler`, or from an MCP client. | `(() => Promise<unknown>) \| undefined` |

#### `ToolCallError`

| Field | Description | Type |
| --- | --- | --- |
| `code` | `"PARSE_ERROR"`: malformed tool-call markup. `"VALIDATION_ERROR"`: arguments fail the tool's schema. `"UNKNOWN_TOOL"`: a call to an undeclared tool. | `"PARSE_ERROR" \| "VALIDATION_ERROR" \| "UNKNOWN_TOOL"` |
| `message` | What went wrong. | `string` |
| `raw` | The model's raw text for this region. | `string \| undefined` |

#### `CompletionStats`

Every field is optional and present only when the backend reports it.

| Field | Description | Type |
| --- | --- | --- |
| `timeToFirstToken` | Time to the first generated token. | `number` |
| `tokensPerSecond` | Generation speed, in tokens per second. | `number` |
| `promptTokensPerSecond` | Prompt-processing speed, in tokens per second. | `number` |
| `promptTokens` | Prompt tokens processed on this turn. Tokens reused from the KV cache are not counted. | `number` |
| `cacheTokens` | Tokens held in the KV cache after the turn. | `number` |
| `generatedTokens` | Decode count. Use it for length and KV-cache budget decisions. | `number` |
| `emittedTokens` | Non-empty pieces the model streamed. Prefer it for usage reporting. | `number` |
| `avgConcurrentSeq` | Mean number of sequences decoded together on the model during the run, including other callers' requests. `1` means the model served this run alone. | `number` |
| `toolDefinitionsDropped` | Prompt renders that left the tool definitions out. Non-zero means the model did not see them; `0` does not prove it saw them all. | `number` |
| `draftTokens` | Tokens drafted by speculative decoding. Present when the model was loaded with `modelConfig.spec_type`. | `number` |
| `draftAcceptedTokens` | Drafted tokens the model accepted. | `number` |
| `backendDevice` | Device that ran inference. | `"cpu" \| "gpu"` |

## Throws

`completion()` returns synchronously and does not throw. Failures reject `final`, `text`, `toolCalls`, and `stats`:

| Error | When |
| --- | --- |
| `CompletionFailedError` | Generation fails mid-stream. `events` still yields the `completionDone` event with `stopReason: "error"` and ends normally. |
| `InferenceCancelledError` | The run is cancelled. Its `partial` field holds the `text`, `toolCalls`, and `stats` produced before the cancel. `events` ends normally on the cancelled `completionDone` event. See [Cancellation](/sdk/runtime/cancellation). |
| `ContextOverflowError` | The request does not fit in the model's context window. `events`, `tokenStream`, and `toolCallStream` throw it too. |
| `RequestRejectedByPolicyError` | The model's wait queue is full. `events`, `tokenStream`, and `toolCallStream` throw it too. |
| `InvalidToolSchemaError` | `tools` starts with a full `Tool` object and a later entry is not a valid `Tool`. `events`, `tokenStream`, and `toolCallStream` throw it too. |
| `InvalidToolsArrayError` | The first entry of `tools` is empty. `events`, `tokenStream`, and `toolCallStream` throw it too. |

## Examples

```ts
import { completion, loadModel, QWEN3_600M_INST_Q4 } from "@qvac/sdk";

const modelId = await loadModel({ modelSrc: QWEN3_600M_INST_Q4 });

// Stream events, then read the aggregated result.
const run = completion({
  modelId,
  history: [
    { role: "system", content: "You are a concise assistant." },
    { role: "user", content: "Explain quantum computing in 2 sentences." },
  ],
  stream: true,
  captureThinking: true,
  generationParams: { temp: 0.7, predict: 256 },
});

for await (const event of run.events) {
  if (event.type === "contentDelta") process.stdout.write(event.text);
}

const final = await run.final;
console.log(final.stopReason, final.stats?.tokensPerSecond);
```

```ts
import { z } from "zod";
import { completion, loadModel, QWEN3_1_7B_INST_Q4, type CompletionParams } from "@qvac/sdk";

// Tool calling: load with tools enabled, run the calls, send the results back.
const modelId = await loadModel({
  modelSrc: QWEN3_1_7B_INST_Q4,
  modelConfig: { ctx_size: 4096, tools: true },
});

const tools = [
  {
    name: "get_weather",
    description: "Get current weather for a city",
    parameters: z.object({ city: z.string().describe("City name") }),
    handler: async (args: Record<string, unknown>) => ({ city: args.city, temperature: "22°C" }),
  },
];

const history: CompletionParams["history"] = [{ role: "user", content: "What's the weather in Tokyo?" }];
const { toolCalls, contentText } = await completion({ modelId, history, tools, stream: false }).final;

history.push({
  role: "assistant",
  content: contentText,
  toolCalls: toolCalls.map(({ id, name, arguments: args }) => ({ id, name, arguments: args })),
});
for (const call of toolCalls) {
  const result = await call.invoke?.();
  history.push({ role: "tool", content: JSON.stringify(result), toolCallId: call.id, toolName: call.name });
}

const answer = await completion({ modelId, history, tools, stream: false }).text;
```

```ts
// Multimodal: attach an image to a user message.
const visionId = await loadModel({
  modelSrc: SMOLVLM2_500M_MULTIMODAL_Q8_0,
  modelConfig: { ctx_size: 8192, projectionModelSrc: MMPROJ_SMOLVLM2_500M_MULTIMODAL_Q8_0 },

const description = await completion({
  modelId: visionId,
  history: [{ role: "user", content: "What's in this image?", attachments: [{ path: "/home/user/photo.jpg" }] }],
  stream: false,

```

```ts
// Structured output that conforms to a JSON Schema.
const { contentText } = await completion({
  modelId,
  history: [{ role: "user", content: "Alice is 30 and works as a data engineer." }],
  stream: false,
  responseFormat: {
    type: "json_schema",
    json_schema: {
      name: "person",
      schema: {
        type: "object",
        properties: { name: { type: "string" }, age: { type: "integer" } },
        required: ["name", "age"],
        additionalProperties: false,
      },
    },
  },
}).final;
const person = JSON.parse(contentText);
```

```ts
// Cancel a run; the promise fields reject with the partial output.
const longRun = completion({ modelId, history, stream: true, kvCache: "session-42" });
setTimeout(() => void cancel({ requestId: longRun.requestId }), 1000);

try {
  await longRun.final;
} catch (error) {
  if (error instanceof InferenceCancelledError) console.log(error.partial.text);
}
```
