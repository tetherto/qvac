The package exports one class, `LlmLlamacpp`, which loads a GGUF model and runs chat inference, batch inference, token counting, prompt caching, and LoRA finetuning on it. It also exports two helper functions and the TypeScript types of every option, message, response, and result. Most applications use this package through the [QVAC SDK](/sdk), which loads models, manages the worker, and exposes one API across languages. For a walkthrough, see [Usage](/ecosystem/packages/llm-llamacpp/usage).

```js
const LlmLlamacpp = require('@qvac/llm-llamacpp')
```

## Classes

### `LlmLlamacpp`

LLM client that wraps the native llama.cpp interface for inference, finetuning, and pause/resume. Create an instance, call [`load()`](#load), run prompts with [`run()`](#run), and release it with [`unload()`](#unload).

```ts
new LlmLlamacpp(args: LlmLlamacppArgs)
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `args` | Model files, load-time configuration, logger, and instance options. | [`LlmLlamacppArgs`](#llmllamacppargs) | Yes |

The constructor validates its arguments and does not touch the model file. It throws a `TypeError` when:

- `files.model` is not exactly one non-empty absolute path, or names a `.tensors.txt` file. See [`validateModelPath()`](#validatemodelpath).
- `files.projectionModel` is set but is not a non-empty absolute path.
- `config.parallel` is not an integer from `1` to `256`.
- `opts.rejectWhenBusy` is set but is not a boolean.

| Property | Description | Type |
| --- | --- | --- |
| `addon` | The native addon, or `null` before `load()` and after `unload()`. Advanced and test access only. | [`Addon`](#addon)` \| null` |
| `opts` | The `opts` passed to the constructor. | `{ stats?: boolean }` |
| `logger` | The `QvacLogger` built from `args.logger`. | `QvacLogger` |
| `state` | Load state. `configLoaded` is `true` between a successful `load()` and `unload()`. | `{ configLoaded: boolean }` |

#### `load()`

Loads the model file in `files.model`, and the projection model in `files.projectionModel` when set, and activates the native addon. A call on an instance that is already loaded does nothing.

```ts
load(): Promise<void>
```

Resolves when the model is ready. On failure, the partially created native instance is released, `addon` stays `null`, and the promise rejects with the native error. A configuration the engine refuses rejects with `InvalidArgument`, for example when `config.device` is missing.

#### `run()`

Runs inference on one conversation, or on a batch of conversations.

```ts
run(prompt: Message[], runOptions?: RunOptions): Promise<QvacResponse>
run(prompt: (Message[] | BatchPrompt)[]): Promise<BatchResponse>
```

The shape of `prompt` selects the form:

| Form | `prompt` | Use it when |
| --- | --- | --- |
| Single | [`Message[]`](#message) | You run one conversation. |
| Batch | An array of `Message[]` or [`BatchPrompt`](#batchprompt) items | The model was loaded with `parallel >= 2` and you run several conversations together. |

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `prompt` | The conversation, in chat-completion message format, or an array of conversations. | [`Message[]`](#message)` \| (Message[] \| BatchPrompt)[]` | Yes |
| `runOptions` | Per-request options. Single form only: a batch sets them per item in [`BatchPrompt`](#batchprompt). | [`RunOptions`](#runoptions) | No |

With `config.parallel >= 2`, several `run()` calls can be in flight at once (continuous batching): separate calls are decoded together across slots, and each returns an independent response that receives only its own output and stats.

When the worker pool is full, the effective `rejectWhenBusy` policy decides what happens. `true` (the default for `parallel: 1`) rejects the call with an `Error` whose `code` is `"RUN_BUSY"`. `false` (the default for `parallel >= 2`) queues the request until a slot frees. Capacity is counted in slots: a batch of N prompts takes up to N. A finetune in progress counts as full at any `parallel`.

**Returns:** for the single form, a [`QvacResponse`](#qvacresponse) that streams the generated text as string chunks; for the batch form, a [`BatchResponse`](#batchresponse). The promise resolves once the request is admitted, before generation ends. Use `response.cancel()` to cancel only that call's job or batch group.

**Throws:**

| Error | When |
| --- | --- |
| `TypeError` | `prompt` is not an array, `runOptions` or one of its fields has the wrong type, `generationParams` has an unknown key, `grammar` and `json_schema` are both set, or `tool_choice` forces a call together with `grammar` or `json_schema`. |
| `TypeError` | The batch form is called with a `runOptions` argument, or batch items set conflicting `rejectWhenBusy` values. |
| `Error` | The model is not loaded: `Addon not initialized. Call load() first.` |
| `Error` with `code: "RUN_BUSY"` | The pool is full and the effective `rejectWhenBusy` is `true`, or the native scheduler refuses the job. Branch on `code`, not on the message. |
| `Error` | A caller-assigned batch id is already in flight in another batch. |
| `InvalidArgument` | A prefill without a `cacheKey` on a model loaded with `parallel >= 2`. |

#### `calcTokens()`

Counts the tokens an input takes on the loaded model, without running it. It never queues behind `run()`, since it reads only load-time state.

```ts
calcTokens(input: CalcTokensInput): Promise<number>
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `input` | What to count. | [`CalcTokensInput`](#calctokensinput) | Yes |

`text` alone is counted raw, with no chat template and no BOS. With `history` or `tools`, the conversation, with `text` (even empty) appended as the last user turn, is rendered by the chat template as the opening request of a fresh conversation, with BOS and the generation prompt, as `run()` renders it. Tools the template leaves out are not counted.

**Returns:** the token count.

**Throws:**

| Error | When |
| --- | --- |
| `TypeError` | `input` is not an object, or one of its fields has the wrong type. |
| `Error` | The model is not loaded: `Model is not loaded`. |
| `InvalidArgument` | Other invalid input, including a media message, or `tools` without `text` or `history`. |

A conversation the chat template cannot render fails as it would in `run()`.

#### `cancel()`

Global cancel: stops every job live at the moment of the call, in flight and queued, across all concurrent `run()` calls, plus any finetuning in progress. The finetune's pause checkpoints are removed from `checkpointSaveDir`, so the next `finetune()` starts fresh. To cancel one request or batch group, call `cancel()` on that call's response instead.

```ts
cancel(): Promise<void>
```

Resolves when the jobs have stopped. On an idle model it resolves without doing anything.

#### `saveCache()`

Writes the conversation kept in memory for `cacheKey` to that file now: the active single-prompt conversation, a batch conversation kept in its slot, or one in the RAM tier.

```ts
saveCache(cacheKey: string): Promise<void>
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `cacheKey` | The `cacheKey` of the conversation, as passed in [`RunOptions`](#runoptions). | `string` | Yes |

Waits for a request running on that key, not for one still queued, so read a response to the end before saving when the file must hold that turn. Writes only when the file lacks turns. Writes ephemeral conversations too.

**Throws:**

| Error | When |
| --- | --- |
| `TypeError` | `cacheKey` is not a non-empty string. |
| `Error` | The model is not loaded: `Model is not loaded`. |
| Native error | Nothing is cached under the key and no file exists, or the write fails. The conversation then stays in memory, unsaved, and the call can be retried. |

#### `discardCache()`

Drops the conversation kept in memory for `cacheKey`, with its RAM-tier entry and its checkpoints, without writing it, so no later eviction or unload writes it. The file, if one was written, is left alone: delete it too to remove the conversation from disk.

```ts
discardCache(cacheKey: string): Promise<void>
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `cacheKey` | The `cacheKey` of the conversation. | `string` | Yes |

Waits for a request running on that key. Resolves when nothing is kept for the key.

**Throws:**

| Error | When |
| --- | --- |
| `TypeError` | `cacheKey` is not a non-empty string. |
| `Error` | The model is not loaded: `Model is not loaded`. |

#### `finetune()`

Starts or resumes LoRA finetuning on the loaded model. Finetuning holds the model exclusively. When a pause checkpoint exists in `checkpointSaveDir`, training resumes from it; otherwise a fresh run starts. Pass the full options on every call, including a resume, and call it only after `pause()` has resolved.

```ts
finetune(finetuningOptions: FinetuneOptions): Promise<FinetuneHandle>
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `finetuningOptions` | Dataset, output, validation, and training parameters. | [`FinetuneOptions`](#finetuneoptions) | Yes |

**Returns:** a [`FinetuneHandle`](#finetunehandle) as soon as the job is admitted. `handle.await()` resolves with a [`FinetuneResult`](#finetuneresult) when training completes or pauses, and rejects on a runtime error. See the package's finetuning guide for the dataset format.

**Throws:**

| Error | When |
| --- | --- |
| `Error` | `finetuningOptions` is missing: `Finetuning parameters are required.` |
| `Error` | `validation` is missing or invalid, a `dataset` validation has no `path` or uses `trainDatasetDir` as its `path`, or the options carry the removed top-level `evalDatasetPath`. |
| `Error` | The model is not loaded: `Addon not initialized. Call load() first.` |
| `Error` with `code: "RUN_BUSY"` | Any inference job is active, or the native scheduler refuses the job. |

#### `pause()`

Pauses finetuning and saves a pause checkpoint, so the next `finetune()` call resumes from it. Also cancels any inference job in flight.

```ts
pause(): Promise<void>
```

Resolves when the pause has completed.

#### `unload()`

Cancels the jobs in flight and releases the native model. Every pending response, batch response, and finetune handle rejects with `Error("Model was unloaded")`. Cached conversations with turns their `cacheKey` file lacks are written to it, unless the conversation is ephemeral.

```ts
unload(): Promise<void>
```

Resolves when the native resources are released. Afterwards `addon` is `null` and `state.configLoaded` is `false`; call `load()` to load the model again.

#### `getState()`

Returns the instance's load state.

```ts
getState(): { configLoaded: boolean }
```

**Returns:** the [`state`](#llmllamacpp) object. `configLoaded` is `true` while the model is loaded.

## Functions

Both functions are static members of `LlmLlamacpp` and also named exports of the package.

### `assessFit()`

Projects one model load against the memory free right now. It reads GGUF metadata, never weight data, so the registry's weightless copy of a model answers the same as the model itself, and the projection can run before anything is downloaded.

```ts
LlmLlamacpp.assessFit(request: FitRequest): Promise<FitResult>
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `request` | The model and the load to project. | [`FitRequest`](#fitrequest) | Yes |

The projection builds the model twice without allocating weights. Concurrent calls run one at a time. Pinning `gpu-layers` in `config` fixes the placement, so the answer is for that exact placement; leave it unset to let the fitter place the model.

**Returns:** a [`FitResult`](#fitresult) with the verdict, the memory each device takes, and the context and GPU layer count the fitter settled on.

**Throws:**

| Error | When |
| --- | --- |
| `Error` | The fitter cannot read the model, the request is invalid, or the machine has no backend device. The message starts with `assessFit:` and names the cause. |

<Callout type="warn">
The projection reads the model's vocabulary, and llama.cpp asserts on a vocabulary it finds inconsistent. An assert aborts the process instead of rejecting. Take the model from a source you trust, or call `assessFit()` behind a process boundary.
</Callout>

### `validateModelPath()`

Validates `files.model` and returns its single absolute disk path. The constructor runs it. For a sharded GGUF, pass only the first shard: the remaining shards are read from the same directory.

```ts
LlmLlamacpp.validateModelPath(files: string[]): string
```

| Parameter | Description | Type | Required |
| --- | --- | --- | --- |
| `files` | The model paths, as passed in `files.model`. | `string[]` | Yes |

**Returns:** `files[0]`.

**Throws:**

| Error | When |
| --- | --- |
| `TypeError` | `files` is empty or not an array, holds more than one path, holds a value that is not a non-empty absolute path string, or names a `.tensors.txt` file. Weight streaming and weight buffers are not supported. |

### `NumericLike`

A number, or a string that holds one.

```ts
type NumericLike = number | `${number}`
```

### `Message`

One entry of a conversation passed to [`run()`](#run): a chat turn, a media message, or a tool definition.

```ts
type Message = UserTextMessage | UserMediaMessage | ChatFunctionDefinition
```

| Value | Meaning |
| --- | --- |
| [`UserTextMessage`](#usertextmessage) | A chat turn of any role. |
| [`UserMediaMessage`](#usermediamessage) | An image, audio, or video file attached as its own user message. |
| [`ChatFunctionDefinition`](#chatfunctiondefinition) | A tool the model may call. Requires `config.tools`. |

### `UserTextMessage`

A chat turn.

| Field | Description | Type | Required | Default |
| --- | --- | --- | --- | --- |
| `role` | The speaker. | `"system" \| "assistant" \| "user" \| "tool" \| "session" \| string` | Yes | — |
| `content` | Plain text, or ordered text and media parts rendered as one turn. Media parts are valid on user messages only. May be empty on an assistant turn that carries `tool_calls`. | `string \| ` [`UserContentPart`](#usercontentpart)`[]` | Yes | — |
| `reasoning_content` | An assistant turn's reasoning, separate from its answer in `content`. An answer sent back with its reasoning inline (`<think>…</think>` first) is split into the two. Ignored on other roles. | `string` | No | — |
| `tool_calls` | Tool calls this assistant turn made, rendered by the chat template in the model's own tool-call format. | [`ToolCallTurn`](#toolcallturn)`[]` | No | — |
| `tool_call_id` | On a `tool` turn: the id of the call this result answers. | `string` | No | — |
| `name` | On a `tool` turn: the name of the tool that produced the result. | `string` | No | — |
| `type` | Left unset on a text message. | `undefined` | No | — |
| `[key: string]` | Any other field. | `any` | No | — |

| `{ type: "media"; content: string \| Uint8Array }` | A media file: an absolute path on disk (`string`) or its raw bytes (`Uint8Array`). |

| `arguments` | The call's arguments: an object, or the text of a JSON object. | `string \| Record<string, unknown>` | No | — |
