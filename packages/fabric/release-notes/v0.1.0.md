# QVAC Fabric Addon v0.1.0 Release Notes

This is the initial release of `@qvac/fabric`, a shared bare addon that hosts the
`qvac-fabric` runtime (Tether's fork of `llama.cpp` + `ggml`) as a single
prebuilt shared library. It follows the same packaging model as `@qvac/onnx`, so
the multi-hundred-megabyte llama/ggml stack is built once, published once, and
loaded once per process instead of being statically embedded into every consumer
addon.

## Features

### Shared qvac-fabric runtime

The package ships `qvac__fabric@0.bare`, a prebuilt shared library containing
`libllama`, `libcommon`, `libmtmd`, and `libggml-base`. It exports the full
`llama_* / LLAMA_* / ggml_* / gguf_* / mtmd_*` C API plus the `common_*` and
`json_schema_to_grammar` C++ symbols, with Linux symbol versioning via
`symbols.map` and macOS export control via `exports.txt`.

### Headers and CMake integration

Compile-time headers ship under `prebuilds/include/` (ggml, gguf, llama, common,
and mtmd). A `find_package(qvac-fabric)` CMake config under
`prebuilds/share/qvac-fabric/` exposes:

- `qvac-fabric::headers` for compile-time includes

### Platform-specific ggml backends

On **Linux and Android**, ggml compute backends ship as separate shared
libraries under `prebuilds/<platform>/qvac__fabric/` and are loaded at runtime
via `ggml_backend_load_all_from_path()`. On **macOS, Windows, and iOS** the
backends are linked statically inside `qvac__fabric.bare` and self-register on
load.

### Consumer integration guide

`INTEGRATION.md` documents how inference addons declare `@qvac/fabric` as an npm
dependency, wire CMake/`include_bare_module`, and pre-load the carrier module from
`binding.js`.

## Backward Compatibility

This is a new package. Existing `@qvac/llm-llamacpp` and `@qvac/embed-llamacpp`
releases continue to embed the runtime statically until they adopt `@qvac/fabric`
in a follow-up release. No migration is required for current consumers of those
addons.
