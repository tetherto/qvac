# Decision models prototype (QVAC-26667)

Tooling for the draft prototype of decision models in QVAC: the
`@qvac/decision-ggml` addon (upstream llama.cpp decision models, Laya included,
through upstream's `server-context`, which it builds from the `qvac-fabric`
port), and `decide()` / `/v1/decisions`. Not for merge; the go/no-go record
lives in the stack's top pull request.

| File | Purpose |
| --- | --- |
| `check-resolution.sh` | Checks that the stack resolves to this checkout's workspace packages, not published copies. |
| `parity.mjs` | Compares `DecisionEngine` with `llama-server` from the same fabric commit: answers per question type against `tolerances.json`, rejections by status, code and message. |
| `requests.json` | The fixed `/v1/systemone` request set. Each request declares its expected outcome (`expect`): `"answer"`, or the rejection's status, code and message. |
| `tolerances.json` | Declared tolerances. **Proposed until the decision owners agree them.** |
| `qvac.config.json` | Plugin list for a decision-only SDK worker (`qvac bundle sdk`). |
| `../../packages/decision-ggml/scripts/decision-parity-collect.js` | Runs the request set through `DecisionEngine` (Bare); `parity.mjs` starts it. |

## Reproduce from a clean checkout (macOS or Linux)

Prerequisites: Git, Node.js with Corepack, CMake, a C++ toolchain, and a Bare
runtime new enough for the repo's dependencies (`npx -y -p bare@latest bare`
works without a global install).

1. Check out the top of the stack and install. The lockfile carries this
   pull request's prototype-only commit, which links `@qvac/inference` to the
   workspace `@qvac/decision-ggml` (unpublished, and not yet declared by
   inference). `decision-ggml` links the workspace `@qvac/fabric` itself:

   ```sh
   gh pr checkout <top-of-stack PR>
   corepack pnpm install --frozen-lockfile --ignore-scripts \
     --filter "@qvac/cli..." --filter "@qvac/decision-ggml..." --filter "@qvac/fabric"
   ```

2. Build, from the repo root. Fabric first: `decision-ggml` links against the
   runtime, and its own vcpkg build of the port (the same overlay) provides
   `server-context`, at the port version fabric records.

   ```sh
   npm --prefix packages/fabric run build         # overlay (fabric PR #497), then link:platform
   npm --prefix packages/decision-ggml run build  # build:ts + build:native
   npm --prefix packages/inference run build
   npm --prefix packages/sdk run build
   npm --prefix packages/cli run build
   ```

3. Check the resolution. Stop if it fails:

   ```sh
   bash scripts/decision-prototype/check-resolution.sh
   ```

4. Reference server, from fabric PR #497's commit, outside this checkout. The
   UI is not needed:

   ```sh
   git clone https://github.com/tetherto/qvac-fabric-llm.cpp && cd qvac-fabric-llm.cpp
   git checkout <F commit>
   cmake -B build -DLLAMA_BUILD_SERVER=ON -DLLAMA_MTMD=ON -DLLAMA_BUILD_TESTS=OFF \
     -DLLAMA_USE_PREBUILT_UI=OFF -DLLAMA_BUILD_UI=OFF -DLLAMA_CURL=OFF -DLLAMA_OPENSSL=OFF
   cmake --build build --target llama-server
   ```

5. Models: llama-server's own test fixtures,
   [`ggml-org/tinylaya-for-testing-gguf`](https://huggingface.co/ggml-org/tinylaya-for-testing-gguf) and
   [`ggml-org/tinyopenjev-for-testing-gguf`](https://huggingface.co/ggml-org/tinyopenjev-for-testing-gguf)
   (with its mmproj). They are pinned in
   `packages/decision-ggml/test/integration/models.manifest.json`. And a real
   Laya checkpoint in upstream format, converted from Hugging Face with the
   converter in fabric PR #497's checkout (the registry's Laya files are
   fabric-format, which decision models no longer load):

   ```sh
   hf download convaiinnovations/laya --local-dir laya
   python convert_hf_to_gguf.py laya --outtype q8_0 --outfile /models/laya-Q8_0.gguf
   ```

6. A worker with only the decision plugin, generated by the checkout's own
   CLI from `qvac.config.json`. The default worker registers every plugin, and
   in this partial install the speech addons cannot resolve their native
   packages. The mobile bundling step that follows reports missing mobile
   platform packages; the desktop `worker.entry.mjs` is already written by then.
   The SDK starts `bare` from `PATH`, so put a current one first:

   ```sh
   (cd packages/sdk && node ../cli/dist/index.js bundle sdk \
     -c ../../scripts/decision-prototype/qvac.config.json --sdk-path . --offline)
   export QVAC_WORKER_PATH=$PWD/packages/sdk/qvac/worker.entry.mjs
   export PATH=<dir with a current bare>:$PATH
   ```

7. Run the SDK example (Laya converted to upstream format, then openjev), the
   CLI, and parity:

   ```sh
   (cd packages/sdk && npx tsx examples/decisions-upstream.ts /models/laya-Q8_0.gguf)
   (cd packages/sdk && npx tsx examples/decisions-upstream.ts /models/tinyopenjev-for-testing-Q8_0.gguf)
   node packages/cli/dist/index.js serve --openai -c <config with a llamacpp-decision model> -p 18434
   curl http://127.0.0.1:18434/v1/decisions -H 'content-type: application/json' \
     -d '{"model":"openjev","input":"Charged twice","questions":[{"type":"predicate","instructions":"Refund?"}]}'
   node scripts/decision-prototype/parity.mjs --server <llama-server> \
     --model /models/tinyopenjev-for-testing-Q8_0.gguf \
     --mmproj /models/mmproj-tinyopenjev-for-testing-Q8_0.gguf --bare "npx -y -p bare@latest bare"
   ```

   `parity.mjs` uses the same model, context (`--ctx`, default 4096), slots
   (`--parallel`, default 2) and offload on both sides. With `--cpu`, both
   keep the model and the projector on the CPU (`-ngl 0 --no-mmproj-offload`
   for `llama-server`). It exits 1 when any request's outcome differs from
   its `expect` on either side, on any mismatch, and when an expected
   rejection's status, code or message differs.

   `llama-server` runs on a free port (`--port` must be free if given). The
   script fails if the server exits before or during the run, or if `/props`
   reports a different model, so results can't come from another process.
